# Arkitektur

## 2026-11-12 kl. 13:39 — Simon Friedl

### Oppgave
Lage arkitekturen for Turplanlegger med `bmad-architecture` (Coaching path). Resultatet skal være en architecture spine som epics, stories og Claude Code kan bygge direkte på. Det trengs ingen presentasjon; faglærer følger arbeidet gjennom loggen.

### Plan
- Lese input: PRD og addendum (final 2026-11-12), faglærerens tilbakemelding, MET-researchen, UX (DESIGN.md, EXPERIENCE.md), Turdatasettet, kalibreringsskriptet og faglærerens `technology.md`.
- Ta de store valgene sammen med brukeren én runde om gangen: språk, rammeverk og hosting, hvor regelmotoren kjører og paradigme, deretter sol, Demomodus, kart, tid og skrift, og til slutt språkmodell, tester og dataverktøy.
- Sjekke teknologi og versjoner mot nettet og npm før de bindes.
- Skrive spinen ut fra memloggen og kjøre Reviewer Gate: lint, avstemming mot PRD og UX, sjekkliste, teknologiaktualitet og en adversarial leser, fem uavhengige gjennomganger.
- Rette funnene og avklare det som var åpent med brukeren.

### Resultat
- **Spine (status final):** `_bmad-output/planning-artifacts/architecture/architecture-turplanlegger-app-2026-11-12/ARCHITECTURE-SPINE.md`, med 19 AD-er, konvensjoner, stakk, tre mermaid-diagrammer (avhengigheter, drift, ett Søk), kildetre, kart fra FR og NFR til arkitektur, og Deferred.
- **Memlogg:** `.memlog.md` i samme mappe, med 62 linjer som dekker alle beslutninger, krav, versjoner og spørsmål. Gjennomgangene ligger i `reviews/`.
- **Valg brukeren tok:**
  - TypeScript i hele appen.
  - Next.js (App Router) på Vercel Hobby (gratis). Railway (5 USD/mnd) og Render ble vurdert; Render sover og bryter NFR-5.
  - Regelmotoren kjører på serveren, med paradigmet functional core, imperative shell.
  - Demomodus med `?demo=<id>`.
  - Leaflet med Kartverkets gråtonekart (`topograatone`).
  - Nunito Sans selvhostet, i stedet for Avenir Next.
  - Claude Haiku 5.5 som språkmodell (Opus 5.5 ble vurdert).
  - Vitest og Playwright, med GitHub Actions.
  - Værtersklene i `data/vaerterskler.json`, felles for appen og kalibreringsskriptet.
  - Ett Zod-skjema for Tur.
  - CSS Modules, ikke Tailwind.
  - `mal_punkt` som valgfritt felt.
- **Funn under kontrollen:**
  - suncalc 1.9.0 gir solnedgang 16:02 den 9. november i stedet for 15:59, og snur UJ-2-eksempelet. Derfor skriver vi NOAA-beregningen selv (AD-11).
  - Kartverkets `topograatone` svarer uten nøkkel (testet).
  - METs værikoner er MIT-lisensiert.
  - Temporal finnes ikke i Node 26.8.1.
- **Funn i gjennomgangen som er rettet:**
  - Formen på data mellom server og nettside var ikke eid. Nå er visningsmodellen ett Zod-skjema (AD-3), og det er tre nye AD-er: Søk-kontrakten med normalisering (AD-17), sidedata (AD-18) og formen på Værmeldingen (AD-19).
  - `/api/begrunnelse` kunne vært en åpen proxy til Claude. Nå regner serveren ut teksten selv.
  - `cacheComponents` er på som standard i create-next-app 16.4.3, og slås av.
  - `@types/node ^20` kolliderer med Vitest 5, og Vitest 5.0.0 har sikkerhetshull. Vi bruker 5.0.5.
  - Koordinatrekkefølgen [lon, lat] mot [lat, lng] er tatt hånd om.
  - Demodata kan ikke lenger havne i MET-cachen.
  - Funksjonsregionen er `arn1`.
- **Lukket i issues.md:** skrift for Android og Windows, dempet bakgrunnskart og lisensen for METs værikoner.
- Arkitekturmappa (spine, memlogg og `reviews/`) er committet i `b83733a` («Arkitektur: spine ferdigstilt») og pushet til `origin/main` sammen med loggcommiten `ec376a9`.
